# 결정 기록
- 2026-10-25. 현재 브라우저의 토큰 자체를 유지하지 않고 기존 웹 인증 전체 폐기 후 새 세션을 발급한다. 사용자는 로그인 화면으로 이동하지 않는다.
- 작업 시작 HEAD 5977d6a, codex/go-platform의 깨끗한 기존 Go 작업 폴더에서 수정한다. Python Modudock 폴더는 수정하지 않는다.
- Passkey 이름 변경은 인증 수단 자체의 변경이 아니므로 세션을 교체하지 않는다. 비밀번호 변경과 관리자 강제 초기화는 기존 전체 로그아웃 정책을 유지한다.
- 계획·실행·TDD 스킬을 사용한다. 사용자의 명시적인 구현 승인을 실행 승인으로 삼아 중간 승인 요청 없이 진행한다.
- RED 확인. MFA 활성화/재설정/재생성 및 Passkey 등록은 signed_out=true, 삭제는 204로 실패했다. 세션 발급 실패 강제 테스트도 기존 코드에서는 200이었다. App 테스트는 복구 코드 화면에서 내비게이션이 없어 실패했다.
- GREEN 확인. 현재 브라우저 새 쿠키/CSRF, 다른 기기 폐기, 이전 CSRF 거부, 발급 실패 원자적 롤백 테스트 통과. 프론트 44개 테스트 통과.
- 추가 경계. 세션 교체 전 요청의 늦은 401이 새 세션을 만료시키는 경우를 테스트로 재현했다. 요청 시 CSRF 스냅샷과 현재 CSRF가 같은 경우에만 전역 로그아웃 이벤트를 발생시킨다.
- 독립 리뷰. 중요 1건: 교체 응답보다 배경 401이 먼저 도착하면 기존 스냅샷 비교만으로는 불충분했다. 응답 200/500/401 세 경우를 RED로 재현한 뒤 changeSecurity가 진행 중인 교체를 추적하고 배경 401 판단을 완료까지 지연하도록 수정했다. 자신의 실패 응답은 기다리지 않아 교착을 피한다. 최종 프론트 48/48 통과.
- 검증. Go `go test ./...` 4개 패키지 통과, core 52.688초. `go vet ./...` 통과. `npm test` 7파일 48개 통과. `npm run build` 타입 검사 및 Vite 빌드 통과.
- Chrome `node scripts/precision-check.mjs .tools/browser-test/node_modules/playwright/index.mjs` 통과. 20개 메뉴 화면, 320/390/768/1024/1440px, 설정 내 복구 코드/저장 확인 후 닫기 및 명시적 로그아웃 후 MFA 로그인 fixture 확인. 데스크톱 인라인 복구 코드 캡처를 직접 확인했다.
- 브라우저 스크립트의 첫 실행은 모바일 메뉴에서 명시적 로그아웃 후 재로그인 시 남은 drawer 상태 때문에 대시보드 heading 접근이 실패했다. 기존 모바일 로그아웃 동작은 이번 보안 설정 변경과 별개이므로 수정하지 않았고, 데스크톱에서 명시적 로그아웃 후 모바일 로그인 경로로 검증했다.
- 리뷰 제외 항목 판단. Passkey 이름 변경·비밀번호 변경·관리자 초기화·SSE 자체는 승인 범위 밖이므로 기존 정책 유지. 비밀번호 변경 시 전체 로그아웃은 계속 필요하다.
- 실기기 지문/얼굴 인증 및 NAS 배포는 수행하지 않았다. Docker 이미지 tar도 재생성하지 않았다. 기존 소스/빌드 테스트만 검증한 변경이다.

# 보안 설정 화면 내 완료 계획

사용자가 승인한 방식대로 MFA 활성화·재설정·비활성화, 복구 코드 재생성, Passkey 등록·삭제를 현재 설정 화면에서 완료한다.

## 설계
- 기존 재인증·단회 proof·TOTP 재사용 방지·WebAuthn 검증은 유지한다.
- 보안 변경과 기존 웹 인증 폐기, 현재 브라우저용 새 세션 발급을 하나의 DB 트랜잭션에서 수행한다.
- 응답은 새 HttpOnly 쿠키 및 csrf_token을 반환한다. 클라이언트는 이후 변경 요청 전에 새 CSRF를 반영한다.
- 복구 코드는 SecurityPage 메모리에만 보관하고 카드 안에서 표시한다. 닫기·이탈·로그아웃 시 제거한다.
- Passkey 이름 변경, 비밀번호 변경, 관리자 강제 초기화 정책은 기존대로 유지한다.
- DB 스키마·추가 패키지·NAS 배포는 변경하지 않는다.

## 실행
1. MFA 및 Passkey HTTP 회귀 테스트와 설정 화면 통합 테스트를 먼저 변경하고 실패를 확인한다.
2. 세션 교체 공통 함수와 네 API 경로에 적용하고 UI의 강제 로그아웃·전체 화면 전환을 제거한다.
3. API 명세·계정 보안 문서를 갱신하고 Go 전체 테스트/vet, 프론트 전체 테스트/build를 실행한다.
4. 독립 코드 리뷰 후 수정 사항을 검증하고 하나의 논리적 변경으로 로컬 커밋한다.

## 검증 초점
- 이전 쿠키·CSRF·다른 기기·재인증 proof는 더 이상 사용할 수 없다.
- 새 세션으로 추가 보안 변경을 바로 수행할 수 있다.
- 세션 발급 실패 시 보안 변경도 롤백된다.
- 늦은 비동기 응답이 이탈/계정 전환 후 복구 코드를 노출하지 않는다.
- 복구 코드 재발급은 기존 코드 무효화와 일회 표시를 유지한다.
